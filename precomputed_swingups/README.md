# 完全下垂起摆的离线控制方案

覆盖 1～5 阶共 57 个目标。每个目标均从小车居中、所有杆 θ=π、所有速度为零开始。

`status.json` 为真实计算进度：

- `queued`：尚未计算；
- `computing`：离线优化、细化或独立验收中；
- `retry_pending`：本轮没有通过，等待更换初值猜测、绕转方向或时长再次计算；
- `ready`：只有该状态可以直接装载运行。

`N-PATTERN.json` 包含离线求出的参考状态、唯一小车控制力、TVLQR 增益，以及独立非线性闭环验收报告。它不是显示动画：真实对象仍每 1ms 用 RK4 求解，参考仅用于反馈控制，不写入物理状态。

界面运行时不调用优化器，不重复验算预计算方案。它检查精确模型参数、完全下垂初值和 SHA-256 摘要后直接加载。修改参数后必须重新离线计算。

执行或续算：

```powershell
python -m triple_pendulum.precompute_all --workers 2 --rounds 4
```

进程按目标分别保存结果，自动跳过已通过项。失败不能被标记为完成；可在页面查看当前已完成数量。普通仓库中的“近目标小扰动收敛记录”不会导入为完全下垂起摆方案。
