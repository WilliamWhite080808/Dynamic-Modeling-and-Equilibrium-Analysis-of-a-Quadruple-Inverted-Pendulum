# 当前动作格式：TOML v2

动作文件使用 `阶数_姿态A_姿态B.toml`，例如 `1_D_U.toml`。每对姿态一个文件，[ab] 和 [ba] 分别是两条独立验收的正反控制路径。文件逐行排版，矩阵每个节点占一行，方向段、参考参数及验收段之间空行分隔。

必需头部只有格式版本 v、阶数 n、两个端点 ends 和共用模型摘要 model。`models/standard.toml` 声明物理参数；摘要按键排序计算，字段排版顺序不改变模型身份。

每个方向的 T 是时长；q/v/a 为广义坐标、速度及加速度节点，u 是唯一小车牵引力，K 是反馈增益。采用原控制器的解析三次 Hermite 基和分段线性力/增益，真实状态仍由被动刚体方程实时积分产生。

h 能从 T/(节点数−1) 逐位准确还原时省略，否则保留。轨道中央、全速度为零的初值及默认目标角度从 U/D 推导，不重复写。必要数值节点保留完整精度，不能把尚不存在的非线性闭式解假写成公式。

hash 是重建后全部控制输入的摘要，origin 是已验收原文件摘要，用于无损核对及来源追溯。proof/worker/direct 保存必要物理与网页 Worker 验收信息。它们不控制动画位置，也不是视频帧。

固定 motions 目录首次无索引时建立缓存；已有索引后只经“检查轨迹更新”手动激活。运行期读取不可变快照。坏文件保留其旧可用版本，不影响正在使用的动作。阶数从有效文件发现，支持后续六阶及更多。

旧 .motion.json 仅保留兼容读取；新发布动作和共用模型均为可读 TOML。以下内容保留此前格式沿革，JSON/省略系数草案不代表本次实际交付。

# 轨迹插件格式

## 当前可交付格式：v1 无损 Hermite 参数插件

2026-11-13 首版使用 `.motion.json`。此前展示的 `.motion.toml` 切比雪夫形式保留在本文后半部分作为未来压缩草案，没有把省略系数的样例发布为动作。

固定目录为 `motions`，一个文件对应一对姿态：`n4_DUUD_UUUU.motion.json`。`v` 是格式版本，`n` 为阶数，`ends` 为两个端点编码，`basis="state-hermite-v1"`，`model_sha256` 指向 `models/standard.json` 的共用物理配置。`ab`、`ba` 分别存独立已验收的正反解，缺一不可；带阻尼的轨迹不能简单倒序。

每个方向仅包含必要控制参数：`T` 总时长、`h` 等距节点间隔、`q` 广义坐标节点、`v` 速度节点、`a` 加速度节点、`u` 小车力节点、`K` 反馈增益节点，及数据摘要/验收依据。初始位置居中、角速度和小车速度为零，角度由端点 U/D 推导；非默认目标绕转才写可选字段。没有逐帧图像或展示状态记录。

令 `z=t/h`、`k=floor(z)`、`s=z-k`，状态节点 `y=[q,v]`、导数 `dy=[v,a]`，参考由三次 Hermite 基解析求值：

`y_ref=(2s³−3s²+1)y_k+(s³−2s²+s)h·dy_k+(−2s³+3s²)y_(k+1)+(s³−s²)h·dy_(k+1)`。

`u` 和 `K` 使用原控制器的分段线性插值。真实状态仍由非线性方程积分和小车反馈产生。保留这些必要数值节点可保证原验收参考逐数无损；尚未用近似拟合去替换已验证控制器。导出会逐条比对完整状态、导数、力与增益的摘要，原文件摘要用于追溯。未来改变参数基必须重新执行物理和 Worker 验收。

首次没有 `.cache/trajectory-index.json` 时扫描有效文件并生成索引及内容寻址快照；以后新增/修改插件只能由界面“检查轨迹更新”激活。索引引用 `.cache/motions` 中的不可变副本，源文件在运行时改变不会悄悄修改当前动作。坏文件保留其原可用快照并报告错误，显式删除在下次检查后生效。阶数入口从有效插件动态生成，可加载六阶及更高阶文件；完整序列入口还必须匹配该阶全量控制摘要及连续验收证书。

当前发布统计以交付包 `release.json` 为准。首版前四阶完整，五阶只发布正反均已验收的部分配对，未把其余单向候选算作完整插件。

# 轨迹插件格式草案

## 文件组织

```text
倒立摆实验室/
  启动实验室.cmd
  index.html
  motions/
    n1_U_D.motion.toml
    n2_UU_UD.motion.toml
    n4_UUUU_UUUD.motion.toml
  models/
    standard.toml
  .cache/
    trajectory-index.json
```

这里只展示与格式有关的目录；完整文件夹还要内含运行环境与程序代码。接收方无需另外找依赖文件。

## 一个插件的最小示意

文件名：`n4_UUUU_UUUD.motion.toml`。

```toml
v = 1
n = 4
ends = ["UUUU", "UUUD"]
model = "standard"

[ab]
T = 6.0
q = [[...], [...], [...], [...], [...]]
u = [...]

[ba]
T = 6.0
q = [[...], [...], [...], [...], [...]]
u = [...]
```

`...` 只用于本说明省略待导出的真实系数，不是一个可直接运行的轨迹文件。两个时长取自这对现有已验收动作；不宣称示意中的参数化表示已经通过验收。

- `U` 向上、`D` 向下，字符从左到右对应从小车起的各根杆。
- `ab` 是 `ends[0]` 到 `ends[1]`，`ba` 是相反方向。阻尼不可逆，两个方向各存自己的已验收参考。
- 单位、质量和长度参数化规则、被动阻尼、重力、轨道、单小车执行器及控制配置在 `models/standard.toml` 共用，不在每个动作中重复。
- 初始小车位于中心且全部速度为零为默认值，端点角度从方向编码生成。有非零绕圈数时增加可选 `turns`，不重复存 `pi` 的数值近似。不同物理参数通过另一个具名模型配置声明。

## 参考曲线的参数化方案

拟采用满足端点约束的多项式基。令 `s=t/T`，`S(s)=10s^3-15s^4+6s^5`，`B(s)=s^3(1-s)^3`。

对每个广义坐标：

`q_ref(t) = q_a + (q_b-q_a) S(s) + B(s) Σ a_k C_k(2s-1)`

`u_ff(t) = s(1-s) Σ b_k C_k(2s-1)`

`C_k` 是切比雪夫多项式。文件中 `q` 是 `[x, theta1, ..., thetaN]` 各坐标的系数向量，`u` 是唯一小车牵引力的系数向量。圈数由可选 `turns` 合入 `q_b`。

速度/加速度由参考曲线解析求导；反馈增益根据共享模型和控制配置生成、缓存，不逐文件重复存储。实际运动仍由被动物理方程积分和小车反馈控制产生，不把参考函数直接当成真实摆杆位置。

这种表示只保留必要参数，不保存截图/视频/逐帧位置等冗余。复杂解可能需要较多系数或另一种分段基，不承诺任意非线性解都有很短的闭式表达。导出时必须重新积分验证终态、稳定保持、轨道、牵引力及变化率，必要时增加系数；验证不通过不发布。

## 索引与激活

首次缺少 `trajectory-index.json` 时扫描 `motions` 建立索引。之后使用已激活缓存，只有点击“检查轨迹更新”才扫描源目录并发布新的有效快照。不会在后台定时把新增文件变成当前动作。

阶数入口和可用方向从有效条目派生；没有对应文件的阶数不显示。缺少反向或未验收的方向不能虚计为已完成动作。
