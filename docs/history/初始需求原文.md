# 完整项目提示词：不可见三重倒立摆高精度仿真与控制

你是一名资深控制工程师、计算物理工程师和 Python 桌面应用开发者。请从零实现一个可运行、可验证、可复现实验结果的“不可见三重倒立摆”高精度计算机仿真项目。项目参考视频《如何稳定不可见的三重摆》，但不要照搬视频画面或仅制作动画；必须真正建立非线性动力学、控制器和状态观测器，让系统依靠算法稳定，而不是使用预录轨迹、关键帧、隐藏约束或直接修改状态。

## 一、最终目标

模拟一辆只能沿水平轨道运动的小车，以及安装在小车上的三级串联被动摆。三个关节均无执行器，系统只有一个控制输入：施加在小车上的水平力。默认目标是将三根摆杆稳定在竖直向上的不稳定平衡点，并把小车保持或移动到指定位置。

项目必须演示：

1. 无控制时，三重倒立摆会快速失稳。
2. 能读取全部状态时，状态反馈控制器能稳定三重倒立摆。
3. 隐藏部分或全部摆杆状态后，控制器仅依据有限传感器输出，通过观测器重建不可见状态并继续稳定系统。
4. 真实状态和估计状态存在初始偏差、模型误差、外部冲击与测量噪声时，观测误差仍能收敛，闭环系统保持稳定或明确报告超出吸引域。
5. 用户能查看模态、极点、可控性、可观性、状态误差、控制力、机械能和求解器误差等数据，而不是只看到动画。

本项目聚焦“直立点附近的稳定与观测”，不把全局摆起作为基础验收要求。可将 swing-up 作为独立的可选增强功能，不能以它阻塞核心功能交付。

## 三、物理模型

采用平面小车—三重串联摆模型。广义坐标为：

`q = [x, theta1, theta2, theta3]`

其中 `x` 是小车水平位置；`theta_i` 是第 i 根杆相对“竖直向上”的绝对角，而不是相邻杆之间的相对角。状态为：

`state = [x, theta1, theta2, theta3, x_dot, theta1_dot, theta2_dot, theta3_dot]`

唯一输入 `u` 是小车水平受力。至少包含以下可配置参数：

- 小车质量 `M`
- 三根杆长 `l1,l2,l3`
- 三根杆质量 `m1,m2,m3`
- 每根杆质心相对近端关节的位置 `c1,c2,c3`
- 每根杆绕质心转动惯量 `I1,I2,I3`
- 小车黏性阻尼、三个关节黏性阻尼
- 重力加速度 `g`
- 最大控制力、最大轨道位置、软/硬限位设置

默认采用有质量、有转动惯量的均匀刚性杆模型，`c_i=l_i/2`、`I_i=m_i*l_i^2/12`；同时允许切换为“无质量杆+端点集中质量”的教学模型。清楚标注两者区别，不能混用公式。

使用拉格朗日法从动能和势能推导精确非线性方程，形成：

`M(q) q_ddot + h(q,q_dot) + g(q) + D q_dot = B u + tau_disturbance`

其中 `B=[1,0,0,0]^T`。禁止把线性化模型当成真实仿真对象。生产代码每一步应通过求解质量矩阵得到加速度，不显式求逆：使用 `solve(M, rhs)`。符号推导可由 SymPy 完成，再生成/缓存高效数值函数；不要在每个时间步执行符号运算。

必须记录并说明角度正方向、坐标原点、质心位置表达式、势能零点和输入符号。给出独立的推导文档，确保公式、代码与动画坐标一致。

## 四、线性化、模态与系统性质

围绕直立平衡点 `q=[x_ref,0,0,0]`、`q_dot=0`、`u=0` 得到连续时间线性模型：

`delta_x_dot = A delta_x + B delta_u`

优先由解析雅可比得到 A、B，并用高精度中心差分或复步长微分作交叉验证。验证误差超过阈值时测试失败。

实现以下分析：

- 开环特征值、特征向量及模态形状。
- 可控性矩阵秩、奇异值和条件数。
- 针对每种传感器配置的可观性矩阵秩、奇异值和条件数。
- 闭环控制极点与观测器误差极点。
- 用图形展示自然模态与设计后的衰减模态。

不要只用“矩阵满秩”一句话判断好坏；同时报告数值条件性。对几乎不可控或几乎不可观的参数组合给出警告。

## 五、控制器

至少实现以下控制模式：

1. 无控制。
2. 连续时间 LQR 状态反馈，使用 CARE 求解。
3. 极点配置状态反馈，作为与 LQR 的对照。

控制律：

`u = u_ff - K (x_hat - x_ref_state)`

要求：

- GUI 中可调整或加载 LQR 的 Q、R 预设。
- 支持小车目标位置阶跃和平滑轨迹。
- 有控制力饱和、速率限制和 anti-windup 所需接口；如果没有积分环节，文档中明确说明 anti-windup 不适用。
- 饱和必须进入真实非线性对象，日志同时记录原始命令和实际施加力。
- 对超出局部控制吸引域的状态，不伪造“恢复成功”；触发失稳/越界标志并给出原因。
- 可选加入参考前馈或积分增广，用于降低模型偏差下的小车稳态位置误差，但不得破坏基础 LQR 模式。

## 六、不可见状态与观测器

至少实现四种传感器配置：

1. `full_state`：全部状态可测，用作基准。
2. `angles_only` 或一个合理的教学对照配置。
3. `cart_and_tip`：只测小车位置与最顶端质点的水平位置；角度和速度不可直接测量。
4. `cart_only`：只测小车位置，用于展示最极端的可观测情形；如果某组参数下数值可观性过差，必须明确显示警告而不是静默失败。

顶端水平位置应由真实几何关系计算：

`x_tip = x + l1*sin(theta1) + l2*sin(theta2) + l3*sin(theta3)`

至少实现：

- 连续或离散 Luenberger 观测器，围绕直立点使用线性模型。
- 离散 Kalman 滤波器，允许配置过程噪声协方差 Qn 与测量噪声协方差 Rn。
- 推荐额外实现 EKF：预测使用非线性对象模型，测量更新使用非线性测量函数 `h(state)`；若实现，必须用 Joseph 形式或平方根方法保持协方差数值稳定，并强制对称化/检查正定性。

观测器的内部模型必须独立于真实对象状态，不能偷读隐藏状态。代码层面通过接口隔离：控制器只能获得时间戳、传感器测量值、参考值和自身内部状态。测试应能证明部分观测模式下没有访问真实角度或角速度。

允许真实对象参数与观测器内部模型参数不一致，以模拟模型误差。支持设置估计初值偏差。显示真实状态、估计状态和误差范数随时间的变化。

## 七、数值精度与实时架构

同时提供两种仿真模式：

### A. 高精度参考模式

- 使用 `scipy.integrate.solve_ivp` 的 DOP853，默认 `rtol<=1e-10`、`atol<=1e-12`。
- 对高增益导致的刚性问题允许使用 Radau，并在报告中显示所用方法、函数评估次数和步长统计。
- 控制器/传感器按离散采样周期运行时，必须按采样事件分段积分，保持零阶保持输入，不能把控制更新频率错误地绑定到绘图帧率。

### B. 交互实时模式

- 物理积分固定步长建议 `dt_physics=0.0005~0.001 s`，默认 RK4；控制更新如 200~500 Hz，传感器更新可单独设置，渲染 60 FPS。
- 使用固定时间累加器，使渲染掉帧不改变物理时间和控制周期。
- 支持暂停、单步、重置、倍速和慢动作。
- 同一初值和随机种子应可复现。

对参考模式与实时模式运行同一短时场景并比较轨迹。给出最大状态偏差，不允许只凭视觉判断精度。

## 十六、扩展为通用 N 重倒立摆

虽然默认演示和基础验收对象是三重倒立摆，但工程架构必须从一开始支持任意正整数阶数 `N`，禁止在核心动力学、控制器、观测器、日志、绘图或 GUI 中把“三根杆”写死。统一定义：

```text
q = [x, theta1, theta2, ..., thetaN]
state = [q, q_dot]
nq = N + 1
state_dimension = 2 * (N + 1)
input_dimension = 1
```

所有杆参数使用长度为 N 的数组或不可变参数对象，包括杆长、质量、质心位置、转动惯量、关节阻尼、颜色及传感器配置。动画、曲线图例、状态标签和导出字段必须根据 N 动态生成。

至少提供 `N=1、2、3、5、8、10` 的预设，其中：

- 1～3 阶用于推导验证、回归测试和教学演示。
- 5 阶用于展示阶数增加后的模态与观测难度。
- 8～10 阶用于高阶实时演示和性能测试。
- 20 阶作为可选离线压力测试，不要求默认实时运行。

用户应能在 GUI 或配置文件中改变 N；改变阶数后，程序自动重建物理参数、状态维度、线性模型、控制器、观测器和显示组件。若某个传感器配置在当前阶数下不可观或数值条件过差，应拒绝启用闭环或明确警告，不能继续使用维度不匹配的旧矩阵。

### 高阶动力学实现要求

不要让高阶系统依赖完整展开的巨型 SymPy 表达式。建议采用以下分层策略：

1. `N<=3`：保留 SymPy 拉格朗日推导，用于生成参考公式和自动测试。
2. 任意 N：通过各刚体质心的平移/转动 Jacobian 自动组装质量矩阵、重力项和阻尼项，或实现递归 Newton–Euler / articulated-body 方法。
3. 用低阶符号结果交叉验证通用 N 阶数值算法。
4. 禁止在每个时间步执行符号微分、符号化简或动态生成 Python 代码。
5. 求解 `M(q) q_ddot = rhs` 时使用线性方程求解器，不显式计算 `inv(M)`。
6. 对矩阵结构适用时使用对称、带状或稀疏求解；记录质量矩阵条件数异常。

基础版本可使用 NumPy/SciPy。性能不足时依次采用：减少临时数组和 Python 循环、预分配工作区、Numba JIT，最后再考虑 JAX JIT。不要为了宣称支持 GPU 而引入不必要依赖。CPU 路径必须完整可用且作为默认路径。

### 高阶控制与观测要求

对每个 N 自动构建相应维度的 A、B、C、Q、R 矩阵。LQR 权重应支持基于物理量的规则化生成，例如按角度、角速度、小车位置和杆序号设置权重，同时允许用户逐项覆盖。

必须报告：

- 可控性和可观性矩阵的秩、最小奇异值及条件数。
- 开环、闭环和观测器极点中最慢与最快时间尺度。
- 控制力峰值、控制力饱和比例和轨道行程。
- 随 N 增加时的稳定时间、估计误差和计算耗时。

理论满秩但条件数极差时，界面应显示“数值上接近不可控/不可观”，不能仅显示“通过”。高阶系统若因单一小车驱动力、有限轨道或有限控制力而无法在给定初始条件下稳定，应将其作为真实实验结果报告，不得取消饱和或偷偷增加关节执行器。

EKF 的协方差维度随 N 增长。高阶情况下允许降低观测器更新频率，使用解析/自动微分 Jacobian、稀疏结构、Joseph 形式或平方根滤波提高稳定性。必须将真实对象推进、控制器更新、观测器更新和渲染耗时分别统计。

### 目标计算机与性能预算

目标机器为 AMD Ryzen 7 7840HS（8 核 16 线程）、约 27.7 GB 可用物理内存、无须依赖 NVIDIA 独立显卡。应针对 CPU 执行路径优化，并设定以下目标而非硬性伪造结果：

- `N=3～5`：高精度仿真、观测器、实时绘图应流畅运行。
- `N=6～10`：默认实时模式应尽量达到 60 FPS；物理步长与渲染帧率解耦，即使渲染不足 60 FPS 也不得丢失物理步骤。
- `N=10～20`：允许降低渲染刷新率或以低于实时速度运行高精度模式，但必须保持数值正确。
- `N=20～50`：定位为离线计算与性能实验；若采用密集矩阵和普通 Python 无法实时，应如实报告。
- `N>50`：只有在递归动力学、稀疏算法或 JIT 优化后再声明支持。

内存不是 10～20 阶的主要瓶颈；重点优化每秒动力学 RHS 评估次数、矩阵分解、Jacobian 计算和 EKF 更新。程序启动时可进行短时基准测试，根据实际速度推荐物理步长、控制频率、观测频率和渲染频率，但不得未经用户确认自动降低积分精度。

### 性能基准与扩展验收

新增无界面基准命令，例如：

```powershell
python -m triple_pendulum.cli benchmark --orders 1,2,3,5,8,10,20 --duration 10
```

输出每个 N 的：

- 每秒 RHS 评估次数。
- 模拟时间/墙钟时间比。
- 平均和 P95 单步耗时。
- 控制器与观测器更新时间。
- 峰值内存。
- 参考模式与实时模式的轨迹误差。

增加参数化测试，至少覆盖 `N=1、2、3、5、10` 的维度一致性、质量矩阵对称正定性、静态平衡、线性化尺寸、控制器矩阵尺寸、日志字段和 GUI 数据适配。`N=1～3` 还应与已知解析结果或符号模型严格对照。

最终交付时不要笼统声称“支持任意 N”。必须列出实际测试过的最大阶数、对应求解器、精度设置、观测器类型、运行速度和是否实现实时显示。
