# 求解器与完整应用实现详解

本文根据本次整理时的实际源码、已保存验收报告和对话记录编写。它解释“解是怎样产生、怎样执行、怎样验收”的全过程，不把历史试验、当前发布快照和尚未完成的搜索混为一谈。对应源码路径均相对于仓库根目录。

## 1. 问题定义与实际承诺

系统是平面小车加 N 根串联的被动摆杆。关节可以自由转动，只有被动黏性阻尼，没有关节电机。主动输入只有小车水平力。用户后来把原始提示词中“直立附近稳定与观测”的核心要求，扩展为完全下垂静止起摆、不同平衡姿态之间的直接转换、失衡恢复和可分享的完整应用。

用户希望尽可能快地立住，且希望任意初值都能恢复。当前实现通过有限时域搜索、轨迹反馈和逐条验收提高成功率；它不是全状态空间可达性的证明，也不是最短时间最优控制器。有限推力、有限轨道和不触壁验收，使某些初值本身不可行，例如小车已经在右端面且仍有向外速度。没有把局部线性极点稳定、一次优化器成功、若干随机初值成功写成“任何初始条件都成立”。

“上下组合稳态”指角度为 0 或 π 模 2π、速度为零的平衡构型。含向上杆的构型通常是不稳定平衡点，需闭环维持；界面中的“稳定”是满足落稳判据，不表示它开环自然稳定。“基态/激发态”沿用用户的操作称呼，不涉及量子态模型。

| 阶数 N | 上下构型 2^N | 除全下垂的目标 | 不同构型间有向边 | 双向成对文件 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 2 | 1 | 2 | 1 |
| 2 | 4 | 3 | 12 | 6 |
| 3 | 8 | 7 | 56 | 28 |
| 4 | 16 | 15 | 240 | 120 |
| 5 | 32 | 31 | 992 | 496 |
| 6 | 64 | 63 | 4032 | 2016 |
| 7 | 128 | 127 | 16256 | 8128 |

公式为：有向边数 `2^N(2^N−1)`，双向文件数再除以 2。用户纠正后的 1/2/3 阶总数为 2+12+56=70；前四阶为 310。数值模型支持更高阶，不代表已经拥有六阶或七阶的完整合格动作库。

## 2. 坐标、参数和刚体模型

源码：`triple_pendulum/model.py`；独立推导：`docs/model_derivation.md`。

定义 `d=N+1`，广义坐标 `q=[x,θ₁,…,θ_N]`，广义速度 `v=[ẋ,ω₁,…,ω_N]`，完整状态 `s=[q,v]`，维度 `2(N+1)`。每根杆的角是相对竖直向上的绝对角，不是相邻关节的相对角。U 对应 0，D 对应 π，角度主值只用于误差与标注，状态可保留连续转圈次数。

默认参数：小车质量 1.5 kg，基础杆长 0.65 m、基础杆质量 0.3 kg，重力 9.81 m/s²，关节黏性阻尼 0.006，小车黏性阻尼 0.08，牵引力上限 120 N，轨道半宽 2.4 m。多杆时杆长从基础值线性递减到 0.78 倍、质量递减到 0.7 倍，以分离模态并改善条件数。默认均匀刚杆的质心距离为 `cᵢ=lᵢ/2`，质心惯量为 `Iᵢ=mᵢlᵢ²/12`；教学点质量模式另用 `cᵢ=lᵢ,Iᵢ=0`，不能混用。

设第 i 根杆远端总质量为 `m_dist,i=Σ(k>i)m_k`，预计算：

```text
a_i = m_i c_i + m_dist,i l_i
H_ii = m_i c_i² + m_dist,i l_i² + I_i
H_ij = l_min(i,j) a_max(i,j)                     (i≠j)
```

质量矩阵为：

```text
M_00 = M_cart + Σm_i
M_0i = M_i0 = a_i cosθ_i
M_ij = H_ij cos(θ_i−θ_j)
```

动力学右端：

```text
b_0 = u − d_cart ẋ + Σ a_i sinθ_i ω_i²
b_i = g a_i sinθ_i − Σ H_ij sin(θ_i−θ_j) ω_j² − (Dω)_i
M(q) q̈ = b(q,v,u)
ṡ = [v, solve(M,b)]
```

`D` 对应相对关节角速度的被动阻尼。耗散功率为 `d₁ω₁²+Σ(i>1)d_i(ω_i−ω_(i−1))²`，非负；这不是控制力矩。程序每步求解线性方程，不显式求矩阵逆，不把线性模型当作真实对象。Python 生产路径使用 NumPy/Numba，浏览器 Worker 独立实现相同的质量矩阵、非线性偏置与 RK4。

机械能为 `E=½vᵀM(q)v+gΣa_i cosθ_i`。有阻尼和小车输入时机械能通常不守恒；无输入、无阻尼的保守测试才适合检查能量误差。全部杆都在同一竖直线时会在画面上重叠，这是该二维模型的几何结果；模型没有杆间碰撞。

## 3. 真正只有小车一个执行器的检查

控制广义力为 `[u,0,…,0]`。独立测试在非零姿态、非零速度下核对：

```text
M(q) · [q̈(u) − q̈(0)] = [u,0,…,0]
```

这直接检查输入有没有偷偷进入关节。显示杆运动的角加速度来自质量矩阵耦合、重力和被动阻尼。

界面 +x/−x 扰动是用户外界冲击，现有实现把有限时长的顶端水平外力通过几何 Jacobian 映射为广义外扰。出现角向广义力项并不等于关节电机：它来自杆端受力。它不作为起摆求解器的额外控制通道。默认扰动持续 0.12 s，恢复会等这次外力结束后才使用受扰状态规划。

## 4. 轨道边界、接触与有效路径

规划在节点把小车约束到 `±0.82 rail`，在配点中点约束到 `±0.84 rail`，给反馈留余量。默认输入参考约束通常取总力上限的 0.66 倍，剩余力供反馈修正；最终验收检查的是反馈后的实际力，仍不得超过 120 N。

运行时保留硬轨道限位。发生接触时，沿小车法向用质量矩阵计算冲量，恢复系数为 0.05：

```text
J = −(1+e) ẋ / (e_xᵀ solve(M,e_x))
Δv = solve(M,e_x) J
```

穿透位置修正只把小车放回端面，不投影摆角。因为质量矩阵耦合，碰撞可以真实改变角速度。已认证的展示路径要求不接触轨道，不能依赖这个碰撞机制把自己弹上来。独立验收要求最大小车位移小于 `0.96 rail`。

## 5. 线性稳定、观测器与适用范围

源码：`triple_pendulum/control.py`、`model.py`、浏览器相应 Worker。

在各目标平衡角处线性化。状态矩阵有块结构：

```text
A = [[0,I], [solve(M,G), −solve(M,D_full)]]
B = [[0], [solve(M,e_x)]]
G_ii = g a_i cosθ_i                    (角度对应行列)
```

用连续代数 Riccati 方程求目标附近的 LQR，反馈 `u=−K(s−s_goal)`。可控性、可观性、闭环极点和部分传感器下的观测器分析来自原始“不可见三重摆”需求。部分观测实验主要用于全直立附近，混合上下目标使用全状态反馈；原始文档中完整测量延迟、丢包、执行器滞后等扩展没有全部实现。

局部 LQR 能稳定邻域，不会让完全下垂静止状态自动跨越全部非线性吸引域。因此必须额外求起摆路径。当前完整包已经实际验证一个自定义近直立初值：`[x,θ,ẋ,ω]=[0,0.06,0,0]`，经真实 API 和非线性积分收敛；这只是一个可复现验收例，不是全局定理。

## 6. 显式 Hermite–Simpson 非线性规划

主要源码：`triple_pendulum/optimal.py`。使用 CasADi 构造自动微分表达式，IPOPT 求解非线性规划。变量是节点状态 `X_k` 和唯一的小车力 `U_k`，时域 T 在每次尝试中固定，节点间隔 `h=T/(K−1)`。

设真实非线性状态方程为 `f`：

```text
f_k = f(X_k,U_k)
X_mid = (X_k+X_(k+1))/2 + h(f_k−f_(k+1))/8
U_mid = (U_k+U_(k+1))/2
f_mid = f(X_mid,U_mid)
defect_k = X_(k+1)−X_k−h(f_k+4f_mid+f_(k+1))/6
```

将每段 `defect_k=0` 作为等式约束，并约束初值为真实完整初值、终点为目标构型且所有速度为零。目标角选取连续绕转角，而非把中间运动限制到 ±π。小车位置与力有硬约束，最终力为零；批处理还要求初始力为零。启用变化率限制时有 `|U_(k+1)−U_k|≤500h`。

当前显式目标函数为：

```text
J = h[0.001 ΣU_k² + 0.01 Σx_k²] + 0.0002 Σ(U_(k+1)−U_k)²
```

它惩罚力、轨道偏移和控制变化。它没有把 T 当成优化变量，因此不能称为严格最短时间求解；“尽可能快”实际通过较短时域先试、失败再扩大/细化来实现。

初猜由三次平滑端点插值、摆动的小车种子和正弦力构造。已有路径会重采样，修正终点绕转角，并用 Hermite 桥平滑匹配实际初始位置和速度。这些操作改的是 NLP 参考变量，不会把真实仿真对象瞬间拉到猜测路径上。

IPOPT 关键设置：目标容差 `1e−8`、acceptable tolerance `1e−6`、自适应 barrier；每次有迭代上限、CPU 与墙钟预算，可响应取消。即使求解器退出，程序也会独立重算数值配点残差和终点误差。当前显式候选成功条件为最大 defect 与终点状态范数都小于 `1e−5`；候选成功仍须通过后续闭环验收。

Windows 中文路径下，CasADi 的插件加载有窄字符路径问题。`optimal.py` 用 `os.add_dll_directory` 保持宽字符 DLL 目录，并在可行时设置 ASCII 相对插件路径。独立包测试必须经过应用实际使用的这段初始化；直接从中文路径裸 `import casadi` 后加载 IPOPT 不能代替真实调用链测试。

## 7. 隐式逆动力学配点

源码：`triple_pendulum/implicit_optimal.py`。困难高阶案例另用等价的逆动力学转录，避免在每个符号约束中都显式展开质量矩阵求解。

增加节点加速度 `A_k` 和中点加速度 `A_mid`，状态导数写成 `[v,A]`，仍用 Hermite–Simpson 缺陷。由逆动力学计算“实现这个加速度所需的广义力”：

```text
required = M(q) A + bias(q,v)
required[1:] = 0                 (节点和中点都要求)
U = required[0]
U_mid = (U_k+U_(k+1))/2
```

因此增加的加速度是优化变量，不是物理执行器；所有被动关节所需的主动控制力矩都受零约束。最终输出仍只有一列小车力。中点和节点同时检查位置、力与被动约束。

代码还保留可选的残差同伦机制：中间数值迭代可以暂时放宽约束以寻找可行初猜，但最终残差界必须回到零；中间迭代不能导出成合格解。当前标准批量搜索在显式和隐式转录之间交替尝试，不因优化器变量中出现加速度就给杆加电机。

## 8. 历史稀疏最小二乘规划器

`triple_pendulum/planner.py` 保留早期基于 SciPy `least_squares` 的 Hermite–Simpson 路径搜索：初末状态误差和动力学残差进入加权 residual，使用稀疏 Jacobian 模式、位置与力 bounds。它还承担当前路径增益计算与参考加密工具。

高阶批量直达路径主要由上面的 CasADi/IPOPT 显式/隐式硬约束方法求解。不能把旧最小二乘的残差权重、早期成功阈值误写成当前所有发布路径的唯一认证标准。最终共同门槛始终是独立闭环物理与实际 Worker。

## 9. 绕转、初猜、网格细化与检查点

源码：`precompute_equilibria.py`。每个方向独立调用 `solve_pair(N,source,target,round_index)`；枚举改变方向杆的 ±π 绕转组合，也在后续尝试给未改变方向的杆增加 ±2π，以探索不同运动分支。

每轮 8 次尝试。`winding_for` 使用 `(round_index*8+attempt) mod 分支数`，避免多轮一直重复同一批转向。基础时域约为 `N+2` 秒，随尝试和轮次变化，上限 11 秒。显式/隐式交替，每次有明确超时预算。

初始网格约 0.03 s；有接近可行的候选后再试 0.02/0.0125/0.008 s 等细化。接近可行但尚未验收的结果保存在 `equilibrium_transitions/candidates`，通过临时文件原子替换。检查点可被后续尝试复用，但不算完成。成功路径、失败/拒绝记录、迭代进度和证书分别管理。

反向路径可以提供初猜：先逆序参考、反向速度，并对小车阻尼做初步力修正，再重新优化或独立验证。被动关节阻尼使整个系统不具备简单时间可逆性，故不能把这一步结果直接贴“已验收逆解”标签。一对插件中的 ab、ba 各自带独立来源和验收，导出审核也逐方向核对。

## 10. TVLQR 与真实闭环执行

源码：`planner.tracking_gains`、`validate_plan.py`、`web/sim-worker.js`。

沿参考状态和力，用中心差分求时变 `A(t),B(t)`。终端条件来自目标 CARE LQR；向后递推 Riccati 矩阵，子步不大于约 1 ms，使用梯形离散化构造 F/G，保持 P 对称，得到节点增益 K。

运行时从节点状态与导数构造三次 Hermite 参考，力和增益做分段线性插值：

```text
e = s_actual − s_reference             (角度误差取主值)
u_requested = u_reference − K(t)e
u = clip(u_requested, −120,120)
u = clip(u, u_previous−500Δt_control, u_previous+500Δt_control)
```

轨迹结束后切换目标附近的 CARE LQR。没有让画布直接按 `q_reference` 摆动；画布读取的是动力学积分状态 `s_actual`。参考路径和真实状态可以不一致，误差过大就无法通过验收。

默认物理 RK4 步长为 1 ms，控制周期为 4 ms，即 250 Hz；默认变化率限制意味着每次控制更新最多改变 2 N。界面渲染由 requestAnimationFrame 驱动，Worker 与渲染解耦。物理计算频率、状态推送频率、显示刷新率和录制 30 fps 是不同概念，不能互相当作性能证明。

这里的 500 N/s 按相邻离散控制指令的差值除以控制周期检查。控制力在 RK4 子步中按零阶保持；程序没有额外模拟真实执行器的连续爬升、带宽、滞后或电机电流动态，因此不能把这个离散指令约束说成已经完成了硬件执行器建模。

## 11. 独立物理验收与 Worker 验收

Python `validate_plan.replay` 从规定的完整初值重新积分；不使用优化器的节点作为真实状态。默认 RK4 为 1 ms，控制保持 4 个子步；高精度复查可以减小积分步长并明确保持原控制周期。

默认落稳条件：

- 所有杆角误差小于 0.5°；
- 所有角速度小于 0.03 rad/s；
- 小车位置误差小于 0.03 m；strict_rest 时小车速度也小于 0.03 m/s；
- 连续满足至少 1 秒。

此外检查最大实际力、500 N/s 力变化率、轨道余量、有限状态值和加权跟踪误差。接纳函数还检查方向、模型、时间、直达质量及来源摘要；具体以 `transitions.py` 和各证书为准。

远端产生候选后，本机 `remote_fifth.py` 下载并核对文件哈希，执行独立 Python 积分，再调用真实页面 Worker 检查。Worker 拒绝或尚未同步的候选不能计入已入库。网页 Worker 还检查没有触轨、没有额外在线规划请求，以及用户切换动作时能正确跳到该动作初值。

“单条方向全部通过”和“整个连续序列通过”是两个证书。后者需要真实末状态连续接续下一段，不能每条偷偷复位。连续证书绑定整个动作库的精确摘要；数据变了就不能沿用旧整库证书。五阶尚未获得完整 992 条及其整序列证书，故完整序列入口保持关闭。

## 13. 自定义初值、耗散恢复和自动再起摆

源码：`planning_service.py`、`recovery.py`、`repository.py`。

求解顺序是精确查已有认证路径/同初值仓库记录；用已有模板对齐连续角、镜像和有限初始偏差，独立检查反馈是否可捕获；尝试直接目标捕获或已有轨迹中间接入；用小车消能回中再接入；最后尝试受限非线性优化。

耗散力采用饱和回中与速度阻尼的组合：

```text
u = −0.4F tanh[kx(x+0.5x³/r²)/(0.4F)]
    −0.6F tanh[kv ẋ/(0.6F)]
```

精确静止在另一平衡构型时允许小车短脉冲打破静止，例如 0.6 秒、12 N 的逃逸激励；总力及变化率仍受限制。恢复的实际状态始终由真实模型连续积分。某次修复将耗散 rollout 同样加上每个 4 ms 控制步最多 2 N 的变化率限制，防止规划模拟和 Worker 的实际执行不一致。

成功记录包含初值、角速度、目标、参数、控制参考、验证结果和可查看历史。相同物理初态的不同 2π 绕转编码可以对齐参考，但不能因此免掉对非同一初值的新验证。老缓存缺少力变化率证明时需要重新检查。找到接入点与已经实际落稳不是一回事，最终从用户初值的整段回放通过才可保存成功。

## 14. 数据插件为何使用 Hermite，而不是把数值假装成解析式

源码：`motion_text.py`、`motion_plugins.py`、`build_folder.export`。

用户要求动作是可扩展的文本插件，并尽量参数化、减少冗余。对于已经得到的非线性数值轨迹，目前没有一个可替代它的简单闭式解。随意拟合少量 Fourier/多项式系数会改变控制参考，旧证书不能自动继承。因此最终选择保留全部必要精度的分段 Hermite 参数，解析的是段内插值基，不是凭空宣称整个受限非线性边值问题有解析解。

实际文件如 `motions/1_D_U.toml`，头部 `v,n,ends,model`；共用物理参数放 `models/standard.toml`；`[ab]`、`[ba]` 分别存独立两方向。每个矩阵节点单独一行，段落之间空行。

| 字段 | 含义 |
| --- | --- |
| T | 固定参考时长 |
| q、v、a | 广义坐标、速度和加速度节点 |
| u | 唯一的小车力节点 |
| K | 轨迹反馈增益节点 |
| hash | 重建后实际控制参考摘要 |
| origin | 对应已认证原始文件摘要 |
| proof / worker / direct | 物理、页面 Worker 与直达验证信息 |

如果 `h=T/(节点数−1)` 能逐位准确还原原 h，就省略 h；否则必须保留。默认轨道中央、零速度、U/D 端点可准确推导时省略重复初值/目标。q/v/a 不能随意删掉：当前状态 Hermite 插值需要完整的状态和状态导数；去掉它们会改变参考。

TOML 会重排标量/表格，旧模型哈希对字典插入顺序敏感。新模型摘要按键排序，允许可读排版不改变模型身份；运行参考 hash 仍与原数据严格一致。读取器兼容旧 JSON 插件，新的发布动作为 TOML。

完整可发布样本必须包含所有节点，文档中有省略号的草案绝不能冒充实解。

## 15. 固定目录、缓存与手动激活

初始化没有 `.cache/trajectory-index.json` 时，扫描 motions、验证参数/端点/哈希/物理证明，建立索引；缓存复制内容寻址的不可变动作文件。阶数从实际有效文件动态发现，不写死 1–5。

已有索引后，运行状态只读已激活快照。源文件新增/修改不能悄悄改变当前动作。用户点击“检查轨迹更新”后才扫描激活；坏文件保留其最后可用版本，并报告错误。整库连续序列许可也受精确摘要约束，删掉一条不能仍显示完整覆盖。

这意味着计算服务累计解数高于便携实例的固定数量是正常的：前者持续入库，后者遵从用户的手动更新语义。创建一个新版本目录并首次建立它自己的缓存，不等于后台修改另一个正在运行应用的动作集。

## 16. 网页、Worker、仓库、时间轴和画面

FastAPI 本地服务负责模型设计、路径请求、仓库与录制持久化。`ThreadPoolExecutor(max_workers=1)` 管理在线规划，request/client 标识及取消事件防止旧任务覆盖用户的新动作。Worker 专注物理，主线程 Canvas 绘制和遥测图表独立。

起点/终点选择器以不同杆颜色的 ↑/↓ 完全展开。切换任一端点立即执行，允许按用户授权显式跳到动作初值，避免“当前位置不在起摆位置就无法点击”。连续序列则从上一段真实末态继续，不能使用这项跳转掩盖衔接失败。

“停止摆动/继续摆动”控制仿真时钟；0.1×–10× 滑块与手动输入调速；稳态保持 5 个仿真秒后循环（2026-11-13 用户最新调整）；时间轴终点为落稳后 0.5 s，拖动通过动力学重积分到指定时刻。路径切换装载中禁止对半完成的状态进行时间轴操作，解决过跳和旧状态竞争。

六组曲线为摆臂夹角、角速度、横向位移、横向线速度、牵引力、系统总机械能。夹角曲线保留连续转角，画布标签可用主值；动态图表有时间窗口和同步游标。绘制层次改为先小车、后杆和关节，使杆在小车前景；轨道全局缩略图和边界始终可见。

仓库展示初值卡片、角度和角速度，可以选择目标或手动输入初值。成功才写入本地 trajectory_repository；浏览器自己的最近成功记录与服务器文件不是同一存储。

## 17. 录制实现及被验收发现的问题

`web/recorder.js` 不截取整个桌面。它重新绘制核心场景、数值和曲线到专用采集画布，通过 canvas.captureStream/MediaRecorder 生成 WebM，目标 30 fps、最高约 1080p。它不采集麦克风、其他窗口或操作栏。文件上传到本应用 recordings，并提供浏览器保存链接。

最终独立桌面验收发现“有文件就算成功”太弱：首次离屏采集可能产生 0 字节文件。诊断对比了画布尺寸、附着方式和编码器。最终采集画布使用软件友好的 `willReadFrequently`，首帧读回后建立流，开始/逐帧主动请求采集，编码完成后才关闭轨道，空 Blob 显示错误且不下载。正常仿真画布仍按原渲染方式运行。

新的验收要求文件至少有实际内容，并在真实浏览器中装载录像，达到可解码状态且 videoWidth>0。Firefox 与自带引擎桌面窗口均通过，不再把空文件或占位下载当作完整录制。

## 18. 完整网页版与独立桌面版

最终目录是 `dist/倒立摆实验室_完整便携包_20261113`，含 网页版/桌面版 两个自包含应用及两个 ZIP。两版都有嵌入式 CPython、NumPy/SciPy/SymPy/Numba/CasADi 等求解依赖及本地服务，不需要收件人再找开发电脑上的散落文件。

网页版 `打开网页版.exe` 显示启动进度，核对本地可执行文件后打开浏览器。它处理了默认 Edge 注册仍存在、实际 Edge 已卸载的情况：跳过不存在的路径，依次找实际 Firefox/Chrome/Edge 等。若无可用浏览器给出具体提示。没有修改用户系统关联或强制重装 Edge。
