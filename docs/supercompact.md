# 超级简：有限有损轨迹

这是用户明确授权的新实验目录 `dist/超级简/桌面版`。它保留现场求解和全部界面功能；原始认证解、`dist/实验`和`dist/极简实验`不被覆盖。压缩目标针对轨迹库，不把完整求解器也承诺缩小十倍。

## 实际尺寸

651对、1302方向的v4轨迹共74,450,160字节，v5共4,423,680字节，为原来的5.94%，约缩小16.8倍。

| 阶数 | 原轨迹字节 | 新轨迹字节 |
|---|---:|---:|
| 一阶 | 14,142 | 2,476 |
| 二阶 | 102,398 | 13,664 |
| 三阶 | 839,634 | 78,429 |
| 四阶 | 10,548,594 | 744,242 |
| 五阶 | 62,945,392 | 3,584,869 |

三至五阶每个插件均不超过各自原文件的10%，最接近上限的为9.9753%。一二阶按用户补充要求优先精度，不硬卡10%。用户指定的 `4_DDDU_UUDU.toml` 从181,566降到9,475字节，为原来的5.22%。

## 为什么能缩小

时间节点、时长、采样间隔均保留，没有抽成少量画面或把摆角当动画赋值。只把q/v/u按明确步长量化为整数；使用固定被动物理预测器产生下一节点预测，保存量化整数与预测整数之差。再对整数差分、ZigZag、字节重排、raw LZMA2和Base85编码。这些后续变换可逆，真正有损的是第一步量化。

加速度和TVLQR根据新参考在固定运行库中重新生成，不再存原a/K的逐位修正。它们不能声称与旧值逐位相同，也不能沿用旧控制SHA或旧序列证明。

实际选用622对第0档、12对第1档、16对第2档、1对第3档。各档步长为：

| 档 | 坐标/角度 | 线速度/角速度 | 牵引力 |
|---|---:|---:|---:|
| 0 | 1e-8 m或rad | 1e-7 m/s或rad/s | 1e-5 N |
| 1 | 1e-7 | 1e-6 | 1e-4 N |
| 2 | 1e-6 | 1e-5 | 0.001 N |
| 3 | 5e-6 | 5e-5 | 0.005 N |

理论舍入误差约为半个步长，另有浮点计算末位误差；最终还逐节点比较实际结果。全库最大参考差：小车2.497微米、角度2.50e-6 rad（约0.000143°）、广义速度2.50e-5（各分量使用其SI单位）、牵引力0.002487N。这些不等于实际闭环轨迹误差上界；实际状态另做独立积分验收。

例子中四阶插件使用第0档：两方向参考位置和角度误差各不超过约5e-9，速度约5e-8，牵引力约5e-6N。

## 文件与验收

v5头部含v、n、ends、model和codec。每方向保存T、h、kind、一个data块及一个check。kind=a是整数预测修正；check保存绑定新完整控制SHA的紧凑物理/Worker验收记录。它是数值验收记录和一致性校验，不是全局数学证明或第三方数字签名。

每一方向重新做1ms RK4积分、4ms控制，参考后继续15个仿真秒，检查稳定、120N、500N/s、轨道安全、跟踪误差和不在第三姿态停留；再用实际页面Worker重新积分。全部1302方向通过后，再用新控制摘要运行各阶完整Euler闭合序列，不复位真实状态/时间/力，不触轨、不请求现场规划。全库解码另逐项核对新验收控制SHA。新模型中的全序列签名只在对应新证书通过后写入。

连续验收发现普通“0.5°/0.03速度/0.03m”的稳定指示不足以保证所有五阶后续路径的接入。仅有损五阶的序列模式收紧真实稳态条件到角度1e-5rad、全部速度1e-4、位移2e-4m，并在进入该范围后计满同样5个仿真秒再切换。它会比普通指示更晚开始稳态计时；没有修改摆角、增加关节力矩或重置状态。单条循环和原无损应用不受这个条件分支影响。

早期16位稀疏参考、补偿力、多项式等候选出现失稳或精度超限，均未交付。最终651对全部使用同一个全节点整数修正方案；未采用的运行分支已经从正式模块删除，原型及失败日志留在results/supercompact。

## 复现与边界

开发机先按[桌面构建](compact-desktop.md)准备固定内核和运行库，再按[库裁剪实验](dependency-pruning.md)准备精简引擎。收件人不需要这些步骤。

使用 `python -m triple_pendulum.build_supercompact prepare --output results/supercompact --assets results/dependency-prune/assets.json` 建立隔离runtime/app。它核对三项固定资产SHA，拒绝覆盖已有runtime/app；已经保留的bank/报告不会删除。后续验证在该解释器中运行，并使用build_compact.pinned_environment()固定BLAS/CPU环境。

1. 在隔离引擎中运行 `tests/build_supercompact_bank.py --workers 4`，通过 `PENDULUM_LOSSY_BANK` 指定新的输出目录。程序按已认证原文件真实路径/SHA读取，选择量化档和整数差分阶次；检查尺寸/参考差，再做新物理和Worker验收。保留已合格检查点。
2. 用隔离解释器运行 `tests/build_supercompact_bank.py --manifest <manifest.json>`，生成精确控制摘要与流式序列输入，仍用PENDULUM_LOSSY_BANK指定目录。展开计划只是可清理缓存，缺失时由小插件和记录重新生成，并核对新控制SHA。
3. `node tests/check-supercompact-tour.mjs <manifest.json> <新证书.json>`，检查全部1～5阶连续序列。验收采用实际新Worker和5秒稳态规则，失败不能开放序列。
4. `tests/check_supercompact_bank.py <验收目录> <解码报告.json> --workers 4`，使用包内解释器逐方向验证新参考还原与新控制SHA。
5. `python -m triple_pendulum.build_supercompact build --bank <验收目录> --tour <新证书.json> --output <新的桌面版目录>`。缺任何单条或精确连续证书、尺寸超限、源文件变动、输出目录已存在均拒绝构建。
6. 独立解压/隔离环境后验证真实普通EXE入口、WebView2与浏览器回退、1×/刷新、时间轴、仓库、录制、随包现场IPOPT求解及手动更新。完整文件夹自己压缩即可，不能只发送EXE。

主体脚本和证据位于results/supercompact。预建索引保留；缺失/损坏可重建，已有应用新增/修改仍须手动检查更新。原始精确解独立保存，未来换版本必须重新验收。当前范围是默认物理参数和已认证初始稳态，不保证任意初值、任意扰动、所有Windows版本或全局最短时间。
